# 1. **Что такое сложность алгоритма**
- **Сложность алгоритма** — оценка ресурсов, которые он потребляет при росте размера входных данных `n`.
- **Ресурсы**:
    - **Время (Time complexity)** — сколько шагов нужно.
    - **Память (Space complexity)** — сколько памяти требуется.

---

# 2. **Асимптотические нотации**

|Нотация|Что показывает|Формула/смысл|
|---|---|---|
|**O(f(n))** (Big O)|Верхняя граница|Алгоритм не хуже f(n) при больших n|
|**Ω(f(n))** (Big Omega)|Нижняя граница|Алгоритм не лучше f(n) при больших n|
|**Θ(f(n))** (Big Theta)|Точная граница|Алгоритм растёт как f(n) при больших n|

> Для тестов обычно используется **O(f(n))** — «худший случай».

---

# 3. **Типичные временные сложности**

|Сложность|Примеры|Примечания|
|---|---|---|
|O(1)|Доступ к массиву по индексу, push/pop стека|Константа, не зависит от n|
|O(log n)|Бинарный поиск|Делим задачу пополам на каждом шаге|
|O(n)|Линейный поиск|Пробегаем все элементы один раз|
|O(n log n)|Быстрая сортировка, сортировка слиянием|Делим + объединяем элементы|
|O(n²)|Пузырьковая сортировка, вставками|Два вложенных цикла|
|O(n³)|Алгоритмы на трёх вложенных циклах|Например, простая матричная умножение|
|O(2^n)|Рекурсивный перебор всех подмножеств|Быстро растёт при n > 20|
|O(n!)|Полный перебор всех перестановок|Используется в задачах типа «коммивояжёр»|

---

# 4. **Типы анализа**

1. **Лучший случай** — минимальное число шагов (например, элемент найден сразу).
2. **Средний случай** — усреднённое количество шагов.
3. **Худший случай** — максимальное количество шагов (используется в Big O).
